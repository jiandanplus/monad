# 断线争城：四阵营真实合约版

新版入口为 `/siege.html`（公开托管也映射 `/siege`）。旧版 `/` 和只读美术预览 `/map` 保留。新合约为 `contracts/SiegeCanvas.sol`，与旧 BlitzCanvas 存储和 ABI 不兼容，必须独立部署。当前默认新版部署配置为空；本地 EVM 验证与私人钱包的 Monad Testnet 验收分别记录，不将本地测试当作测试网多人上线证明。

## 玩法

每局300秒，四个阵营等额配置1至4席，共4、8、12或16个不同钱包地址。房主配置名单，每个地址亲自发送准备交易；全部准备后房主开局。名单和开局均有预期版本，活动局禁止改名单或重开。

13个设施通过20条权威道路连接：四个基地、四个矿场、四座城区通信塔、中央兵工厂。补给只沿己方占领的设施，从本方基地出发计算。矿场连通才增加军费收入；通信塔连通才累计统治分；兵工厂连通才可生产。切断补给不会让已有部队消失，也不阻止其出兵作战；重新连通不会补发中断期间的收益。以300秒内累计统治分决胜，同分并列。

军费为阵营共享的局内数值，初始100、上限200，基地基础收入每秒1，每个连通矿场额外每秒1。通信塔每秒1统治分。占领先结算四方原有收入和分数，再改变归属；没有即时占领奖励。资源和分数在回合结束时停止增长。

| 单位 | 招募军费 | 满血 | 特点 |
|---|---:|---:|---|
| 步兵 | 20 | 10 | 优先攻击坦克；城区防守时更抗伤、反坦克更强 |
| 坦克 | 50 | 30 | 优先攻击步兵；单独清空守军后不能占旗，会带残血返回 |
| 工程师 | 35 | 8 | 无直接伤害；可接管空点，支持修筑和修复 |

初始每方基地有3步兵、1坦克、1工程师，中立点各有2步兵。基地可以撤回本方部队，不能攻击敌方基地。每点最多12单位，每次派1至6个实际单位，调遣本身不额外扣军费；招募才购买新增单位。部队保留战损。每次来源行动冷却3秒，同队多人共享来源版本与冷却。队友先操作后，旧选择会被拒绝，不能把过时索引当作新兵力。

战斗最多3轮，双方按该轮开始时存活部队同时开火。类别伤害汇总后优先作用于同类别低血单位，同血按原索引；伤害不跨类别溢出。城区步兵先承受75%整数向下取整伤害，有工事再乘80%取整。守军清空且进攻方剩步兵或工程师才占领。三轮未分胜负则进攻残部返回。工事战后消耗。

修筑花20军费，要求有工程师、补给连通、己方非基地、尚无工事。修复每次合计15军费，选择1至3个残血单位，各恢复10HP且不超过满血，要求同点有工程师与补给。连通兵工厂可招募步兵和工程师，坦克只在基地生产。

## 钱包验收步骤

1. 在支持自定义 EVM 网络的钱包浏览器打开新版入口，选择 Monad Testnet（10143）。准备至少四个不同、本人能签名的私人钱包地址和测试 MON；首次验收建议每方1席。只提供公开地址，不提供私钥、助记词或钱包密码。
2. 选择实际授权账户，点击部署 SiegeCanvas，复核页面后由人完成钱包签名。部署者是房主。部署成功后页面核验运行代码、部署回执和同块快照，显示可复制的房间链接。
3. 全员打开同一个含 `contract` 和 `start` 的新版链接。房主填四方名单并签名配置；每席切换到对应地址，重新连接并亲自签名准备。房主再签名开启300秒回合。
4. 每方至少一次“来源→实际单位→相邻目标→复核→钱包签名”。记录四个地址各自的成功交易哈希、区块、事件与公开只读快照。
5. 实际攻占矿场与通信塔，再夺取对方关键连接，核验断线停止对应收入/统治分；重新连接后从恢复时刻继续，不能补发中断时段。核验残血、修复、工事、队友共享军费和300秒截止。

最终签名始终由人完成。钱包显示风险警告时不要关闭防护；可用本机构建页面验收，再把通过核验的房间链接复制出来。没有应用收费、资金托管、下注或代币收益，只使用测试 MON 支付网络 gas。

拒签和链上回退没有本地战果。广播后确认超时，页面保存公开交易哈希与原指令并锁住重复发送；点击重新核验。若在页面关闭后用钱包加速或取消，可填写钱包最终交易哈希，系统先检查原账户、nonce和 canonical 区块，再恢复或解除原指令。首次因传播延迟查不到原交易时，重核会重新获取并验证其详情；若RPC仍无法提供原交易及nonce，状态保持未核验，不能仅凭新哈希宣称原指令已取消，需保留哈希并在钱包核对。部署恢复使用最终部署交易哈希。待处理订单属于另一房间时，先只读打开原房间再核验，切房不会清除交易锁。

## 技术结合与边界

每次名单、准备、开局、招募、调遣、修筑和修复都是独立 nonpayable EVM 交易，Solidity 决定权威结果。前端核验网络、精确运行代码、发送者、合约、完整 calldata、成功回执、事件及区块；只有一致快照更新实际兵力，确认动画是事件回放。战损预览由纯规则模型计算，明确标注为预览，不能代替合约执行。

时间收入采用检查点按需结算，不需要每秒交易或后端 keeper。四方共享军费、争夺同点、补给变化形成真实依赖；不同阵营、不同来源的指令可提供独立工作，但此版本没有测得或承诺 Monad 网络 TPS、最终性或平均确认速度。占领结算四方检查点有必要的共享依赖，不能宣称所有指令都可并行。

等距场景支持拖动、缩放、小地图、点选、同源框选和右键目标。单位与归属只读实际快照；没有有效合约时不生成示例军队。近期战报只读最近100区块、最多6笔完整核验的交易，并非全量历史索引。没有随机事件、隐形AI对手、行军延迟或途中拦截；道路动画在确认后播放。

## 构建与本地验证

`npm ci` 安装锁定依赖，`npm test` 运行模型、真实本地EVM、交易与界面行为测试，`npm run build` 用Solidity0.8.30、Shanghai、viaIR、optimizer200编译两份独立合约，并运行 TypeScript 和三入口 Vite 构建。Node22.23+；原版生成物应保持不变。`npm run dev` 后打开终端给出的 `/siege.html`。

生产构建是静态站点。默认读取 `public/siege-deployment.json`，未部署时保留 address=null；通过验收后才填真实地址和部署区块并重新构建。复制配置不等于部署，旧版地址不能填入。严禁将本地验收脚本、自动签名测试 provider、私密配置或密钥放进发布文件。

只读导出新版证据：`node scripts/verify-siege.mjs <合约地址> <部署区块> evidence.json`。它核验当前同块快照和最近100块最多24笔行动的实际回执，记录各阵营观察结果，不发交易、不请求签名。`--local`只用于固定的127.0.0.1:8547本地验收，输出会明确标注local-evm；所有输出的testnetAcceptancePassed默认false，不能用本地数据自动宣称真人测试网验收通过。
